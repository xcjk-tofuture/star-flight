# 遥控接收与校准状态

本板使用接收机SBUS输出接PC7（USART6 RX），当前MCU接收配置恢复为旧版`977d5b0`的
100000、8个有效数据位、偶校验、1停止位；USART6只接收。标准SBUS发送格式含2停止位，
这里保留本板2024版本已使用的接收配置，CubeMX与源代码同步为1停止位。
HAL的9B+Parity=EVEN表示8个有效数据位。标准SBUS是反相逻辑，F407没有UART硬件反相；
现有板上反相电路或接收机的非反相SBUS输出需按实际接线确认。

旧逻辑有三处会影响显示或接收：

- 没有八通道有效校准范围时，控制快照Connect_State为0，GUI将其显示成接收机未连接。
- IDLE DMA数据只有恰好25B才被接收，拆成两块或合并成50/75/100B均被丢弃。
- 帧尾只允许0x00；SBUS2的0x04/0x14/0x24/0x34被拒绝。

现在按字节重组25B帧，坏帧重新寻找头，部分帧超过20ms间隔时重同步。
frame-lost单帧只计数并保留前一健康值，超过100ms没有健康数据仍判失联；failsafe立刻禁止控制。
DMA块附带实际接收毫秒时间，任务处理不把积压包伪装成刚到的数据。
通过门限的健康原始数据、有效校准范围和控制可用性分别呈现；控制仍要求校准完整及数据新鲜。

| 新界面/日志 | 含义与操作 |
|---|---|
| 待遥控 / chunks=0 | 暂无接收数据；确认供电、共地、PC7、SBUS输出与反相链路 |
| chunks增加、frames=0 | 有字节但无法拼成合法帧；看bad/skipped、输出协议、波特率与极性 |
| 遥控失联 / fs增加 | 接收机仍输出帧，但发射机失联或failsafe；不允许解锁 |
| 遥控待校 / raw=1 cal=0 | 链路健康但无有效校准；通道页可看原始值，做八通道校准 |
| raw=1 cal=1 | 原始数据和校准范围可用；仍需满足惯导、状态守卫等解锁条件 |

进入遥控校准后覆盖八通道全部范围；K1长按进入“保存退出”，K2长按取消并恢复原范围。
已提交Flash保存时等待具体写入结果。`invalid=0x20`表示CH6范围未通过，依次检查对应通道。
校准后CH5负责地面/准备/自稳，CH6负责安全/急停，CH7/8旋钮只控制UI；解锁手势与遥控UI操作见 [RC_CONTROLS.md](RC_CONTROLS.md)。
重做校准时独立UI快照可沿用上次有效范围，控制快照仍不可用；保存成功提示等待Flash读回完成。
本次只读设备诊断得到rc_sequence=0，表明当时未加载有效遥控范围；不能仅凭此证明PC7上已有健康SBUS信号。
新版每5秒输出SBUS日志，用于继续区分接线、帧格式和校准问题。真实接收机验收待烧录后进行。

## 帧错误后接收停住的修复

2026-10-08实机日志：`chunks=9 bytes=224 frames=8 RX=0 raw=0 age_ms=144940 uart_error=0x4`。
本工程HAL定义`0x4=FE`（帧错误），`0x2=NE`（噪声）；不是仅缺少校准记录。
旧错误回调在IRQ里直接尝试重启且忽略返回值，失败后没有任务重试，接收可以长期停在READY。

新错误回调只记录累计错误、立即撤销控制可用性；SBUS任务每20ms检查UART与实际DMA运行状态，
结束残留传输、清理错误标志并重启ReceiveToIdle DMA。异常DMA状态通过公开HAL接口重建；
连续失败时只重新初始化USART6，不复位MCU。重新启用后丢弃旧队列/半帧，等新的健康帧再恢复连接。
常规IDLE接收回调保持原流程，SDK/HAL源码未修改。

新增`SBUS_RX`日志分别累计PE/NE/FE/ORE/DMA错误、尝试/恢复/失败次数，以及last_error/last_hal。
烧录后先看`RX=1 raw=1`和frames持续增加；`cal=0`时再做遥控范围校准。
若FE等错误持续增长，需要进一步测量反相电路的波形、电平与供电，软件恢复不代表波形已正确。
